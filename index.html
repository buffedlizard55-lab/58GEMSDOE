Executive summary

No submission file has been generated yet. The competition data (feature rasters, fault labels, example submission) is behind a DrivenData login, and this sandbox cannot reach it. Without that data we cannot build a real fault map, run the holdout, or run the leakage canary. A file made without the data would not be a prediction, so none was produced. The writer and validator are ready. Once the data is in data/ and a probability map exists, one command writes and validates the GeoTIFF.
What the file must be
  • One band, float32, GeoTIFF (.tif), or a .zip holding one GeoTIFF.
  • CRS EPSG:32611, 100 m pixels, same width, height, and transform as the sample submission.
  • Values in [0, 1] inside the scored footprint; NaN outside it.
  • A unique name and a note of 140 characters or fewer.

Full step-by-step guide: SUBMISSION_GUIDE.md.

How to submit

  1. Get the data. Register on DrivenData and download the files into data/. We do not bypass the login.
  2. Check the data. 
    python scripts/check_data.py
    Writes data/inventory.json with grid alignment, label counts, and a per-band leakage canary (AUC above 0.90 is a leakage suspect).
  3. Make a probability map. Model work is not built yet. Save a (3730, 3292) float array in [0,1].
  4. Write and validate. 
    python scripts/make_submission.py prob.npy submissions/NAME.tif --reference data/example_submission.tif
    The command exits 0 only when every check passes.
  5. Check the rules (eligibility, deadline, AI disclosure). The rules could not be read from this sandbox.
  6. Upload the .tif with its name and note, then copy the receipt score.
