Why the earlier "Predicted values must be in range [0, 1]" error happened

That message is raised when any cell is outside [0,1] or is not finite (NaN/inf). Files that write NaN outside the study-area footprint trip it. This file uses the all-finite policy: dots at exactly 1.0, explicit zeros everywhere else including outside the footprint. The writer (src/gems57/submission_writer.py) validates in memory, writes to a private temporary path, re-opens the file on disk and re-validates it, and only then atomically publishes .tif + .zip + a JSON receipt. If any check fails nothing is published.

What the numbers on the main page are, and are not

  • HOLDOUT-DTI — measured on the hide-and-recover instrument with the shared exact evaluator. Evidence about the method, never a leaderboard projection.
  • USER-REPORTED-SCORE — a score quoted on an owner page. Not an organizer receipt.
  • ORGANIZER-CONFIRMED — copied from a submission-page receipt. None exists for this file yet.
  • ESTIMATE — derived (here, the implied truth-set size). Never a score.
