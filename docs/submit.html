How to submit (step by step)

Based on the official rules and the competition's submission page wording. Verified 2026-10-11 from the rules PDF and problem page.

⬇ Download the GeoTIFF

Steps

  1. Eligibility and registration. Create a DrivenData profile and register for the challenge (rules §3.1). Individuals must be U.S. citizens or permanent residents; the registered person must certify eligibility (rules §1.3, §A.1). Only the registered person can do this.
  2. Download 58GEMSDOE-ribbon-lane-v1-20261011.tif from this site.
  3. Check it (optional, local): from the repository root run PYTHONPATH=src python -m gems58.validate 58GEMSDOE-ribbon-lane-v1-20261011.tif --reference sample_submission.tif (the reference is your local copy of the official sample). Every check must read true.
  4. Open the submission form on the competition's submission page and click File to submit → choose file. Upload 58GEMSDOE-ribbon-lane-v1-20261011.tif as a single-band GeoTIFF (.tif). It must match the submission format's CRS, shape and geotransform.
  5. Name it. Use the unique name 58GEMSDOE-ribbon-lane-v1-20261011.
  6. Add the note (≤140 characters): Ribbon lane v1: geophysical ridges, class-wise dotted lines; holdout DTI 0.037 (CI 0.006-0.068). Format-valid. Not promoted.
  7. Submit. The limit is three submissions per week (rules §3.2, §3.4). Do not exceed the weekly cap shown on the page.
  8. Final selection (team decision). Before the deadline you must choose exactly one submission for both prize rounds (rules §3.4, §3.5). Do not choose on the basis of this site alone.

If you see “Predicted values must be in range [0, 1]”

That error means a value inside the scored area is outside 0–1 or is not a number. The GEMSDOE32 owner documents two causes: a large negative nodata sentinel (−3.4028234663852886e+38) left inside the footprint, and NaN inside the scored region (source). This file has values exactly 0 or 1 inside the footprint and NaN outside it. The validator checks both. If the error still appears, the problem is in the file that was uploaded, not in this one: re-download and compare the sha256 above.
