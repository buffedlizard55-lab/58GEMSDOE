Why every emitted dot is exactly 1.0

With the official metric DTI = TPw / (TPw + α·FPw + β·FNw + ε), α = 0.2, β = 0.8, and the triangular kernel k(d) = max(1 − d/R, 0), R = 300 m = 3 px, a truth pixel takes the maximum kernel value over all predictions while a predicted pixel pays its own value times the leftover kernel. Scaling a dot down therefore scales its credit down without reducing the fixed β·FN term, so on a fixed support DTI is monotone increasing in emitted mass and the optimum is 1.0 everywhere you emit. Verified algebraically in evidence/ribbon/theorems.json and numerically by the positive_is_exactly_one check above (unique positives = [1.0]).

What the portal does with dots on the mapped catalogue

Nothing: the organizer masks known USGS/INGENIOUS fault pixels out of evaluation in both rounds, so a dot there earns no credit and costs nothing. This file has 0 such dots — the emitter drops them, which keeps the whole budget available for off-catalogue placement (and, on the local holdout, keeps the withheld truth scoreable instead of reading exactly 0.0 — IR-58-02).
