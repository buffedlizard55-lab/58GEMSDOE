# Ranked, untried hypotheses — ribbon-width lane only

**Status: proposals, not results. None was implemented or evaluated in this review.** The literal registry gate is currently blocked, so these are queued only; do not start an experiment until the surface uniqueness gate can be run on a current complete accessible inventory and does not trigger.

## Scope and prior-session audit

The official target is geological faults indicative of geothermal resources; a ribbon-width change can only improve placement around a ridge already detected. It cannot recover a fault for which the fixed ridge surface has no candidate. The proposal therefore concerns where a near-trace ridge is systematically mislocalized—not a new geological detector.

All candidates use the cached competition `training_features.tif` (19 raster-described bands, 100 m EPSG:32611 grid) and existing magnetic, gravity, topographic, or geodetic ridge surfaces. No new external dataset is required. The local file is reconstructed from five SHA256-pinned parts in an owner-maintained GitHub bridge; that verifies byte integrity against the bridge, not independent organizer provenance. Official problem page: [GEMS Prize task and provided features](https://www.drivendata.org/competitions/306/competition-doe-gems/page/967/); source and raster metadata record: [`docs/SOURCES.md`](../SOURCES.md), `data/bridge/feature_stack_pins.json`.

Prior code/evidence review:

- `src/gems58w/sigma.py` measures a censored isotropic nearest-ridge distance and summarizes strata with median/RMS; it does not fit a cross-fitted signed cross-strike bias or an empirical directional stencil.
- `src/gems58w/allocation.py` uses a symmetric Normal error model and a 3-px offset lattice. Historical fixed-width sweeps exist, but their split/selection and uncertainty are not promotion-grade; they are not evidence for the proposals below.
- `src/gems58w/holdout.py` contains a `signed_offset` helper, but the prior emitter does not use it to fit/test held-out directional ribbon offsets. The old `H58-T` page proposed a broad tensor-direction idea but did not validate it. Candidate 1 is a specific robust signed-bias test and is related to that unrun proposal; it is **not** claimed as wholly unprecedented.
- Old E1/E2 results are disqualified for promotion. No numeric uplift is inferred from them.

A local-relief-conditioned σ could keep ribbons tight in clean terrain and wider only where an existing scarp ridge is more displaced from a concealed trace. | Current σ strata include family, sign, scale and block, but no local-relief-conditioned width. A stable training-only signed normal bias might justify shifting the ribbon centerline rather than spending dots symmetrically. It can help only where the existing strain ridge is already near an unmapped fault. | The prior calibration pools unsigned distance; no cross-fitted, family/scale/sign-specific signed offset is used to choose a centerline. | **Low–moderate** potential; **high** uncertainty; **medium** cost. | Station geometry, atmospheric/InSAR noise, anthropogenic subsidence, and block-boundary artifacts. |
| **4** | **Empirical-tail width for gravity edges.** `iso_grav_anom`, `iso_grav_anom_hg`, `iso_grav_anom_vg`, `iso_grav_anom_slope`; existing gravity ridge surfaces. | Density contrasts associated with basement offsets can be broad and have heavy-tailed localization errors under variable sediment cover. An empirical held-out error distribution may allocate a limited number of lines to the useful tail better than a single RMS/Normal assumption, while retaining a narrow core. | Current lane compresses localization error to a scalar scale and the old plan assumes a symmetric Normal distribution. Fit empirical signed-distance quantiles on training blocks and select only a preregistered small set of stencils. | **Low** potential; **medium–high** uncertainty; **low–medium** cost. | Regional density trends, batholith edges, sediment thickness changes, and processing seams. |

These are qualitative rankings, **not** performance estimates. “Benefit” means relative likelihood of improving exact outer-block DTI for the same dot budget; the private expert-labeled score set is unavailable, so no proxy result establishes prize-round performance.

## Preregistered common test and stopping rules

If and only if the registry blocker is resolved:

1. Before placing any dots, compare the frozen candidate ridge surface with every current accessible registry raster. Stop and record a negative if Spearman rank correlation is >0.90, if >70% of candidate support/dots fall within 3 px of any one raster, or if the inventory is stale/incomplete. No dense-raster exception is authorized.
2. Use the shared cached feature stack, a buffered whole-component spatial split, `gems57.evaluate_holdout` and `gems57.submission_writer`. Catalogue-derived context must be computed from visible faults only; mask visible faults pixel-exactly. Do not use the withheld pixels to accept candidate segments, choose a σ/stencil, or tune a threshold.
3. Run a feature-alone leakage canary first. AUC >0.90 is leakage until independently explained; stop rather than tune around it.
4. Preregister one primary width/stencil comparison and one dot budget. Fit the width/bias using training blocks only, then evaluate once on untouched outer spatial blocks. Use exact max-credit `ΔTP` and `ΔFP` under the shared metric; do not use the isolated-dot shortcut for interacting patterns. Report HOLDOUT-DTI with evaluator version, withheld-positive count, protocol, and a defensible 95% CI.
5. Stop if the paired primary result is nonpositive or the 95% CI does not support the preregistered improvement rule. No follow-up sweep merely because the result is weak. At most three experiments and two hours total.
6. No slot is selected or used. The current status remains **NOT OK TO SUBMIT — DO NOT SUBMIT** until every holdout, pre-placement, final-dot, inventory, and format/validation gate clears.
